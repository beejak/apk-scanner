# Sandbox scan results (public training apps)

These reports were generated by running the local CLI against **freshly downloaded** educational / intentionally vulnerable artifacts in a disposable temp sandbox. **APK / IPA / similar binaries are never stored in this repository** (see root `.gitignore`).

## How to open reports

1. Prefer **`capability_run_YYYYMMDD/manager_report.html`** — self-contained CSS + tables (works with a normal double-click / `file://` URL; no local server required).
2. In File Explorer: double-click the HTML file, or right-click → Open with → your browser.
3. Or paste into the address bar, for example:  
   `file:///C:/Users/…/apk%20scanner/docs/results/capability_run_20261014/manager_report.html`
4. Older pages that `fetch()` a sibling `summary.json` may fail under `file://` (browser CORS). Use the manager report or open via a tiny static file server if you need those.

Also linked from [`index.html`](index.html) and [`../capabilities.html`](../capabilities.html).

## How these were produced

1. Create `%TEMP%\apk-scanner-capability-<timestamp>\` (or similar).
2. Download public training samples (APK / IPA / JAR / extract `.so` / SDK-like dirs).
3. Run: `python cli.py <sandbox> --sast -o json` (also html/csv/text). Use `--dynamic` only if `adb` + a device are already available.
4. Copy **sanitized** reports here (paths redacted to `<sandbox>`). Keep manager HTML + optional `summary.json`.
5. **Purge** the entire sandbox (binaries + local report copies).

Regenerate anytime; do not commit APKs/IPAs.

## What this shows

Pattern-scan / metadata-heuristic **leads**, not confirmed vulnerabilities. Vague `password` hits remain noisy (low severity). High-confidence formats (e.g. AWS `AKIA…`) and metadata rules (debuggable, allowBackup, exported unprotected) are more actionable. Reports include **severity_score**, taxonomy DBs, **CVSS-estimate** (rule-based), and **remediation/revalidate** text. No invented CVE IDs (SCA backlog).

## Planned local drop-zone UI

A static HTML/JS drag-and-drop page **cannot** run this Python scanner in-browser. A future UI needs a companion local server or Tauri (or similar) wrapper that invokes `cli.py`. That UI is **not** built here — only documented.
